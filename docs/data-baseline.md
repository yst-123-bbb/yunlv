# 数据源现状基线抽样（data baseline）

本文件建立数据质量改进前的**对照基线**：记录抽样口径、逐条核对表与当前错误率数值。
后续 C-HEALTH@1 体检报表（`datastore/health_report.py`）的数值与该基线对比，用于判断改进是否生效。

## 1. 抽样口径

- **数据来源**：`data/*.py` 的旧兜底数据，未经数据库写入，直接按模块常量读取：
  - `attraction` ← `data/attraction_data.py::_ATTRACTION_DB`（城市 → 景点列表）
  - `restaurant` ← `data/food_data.py::_FOOD_DB`（城市 → 餐厅列表）
  - `hotel` ← `data/hotel_data.py::_HOTEL_DB`（城市 → 酒店列表）
  - `train_route` ← `data/train_data.py::_PAIRS`（"出发-到达" → 车次元组列表，一个线路计一条）
  - `flight_route` ← `data/flight_data.py::_TIMES`（航线元组列表，一个航线计一条；双向航线按"城市对"去重）
- **抽样规模**：每个品类最多 50 条；样本池不足 50 条时全量纳入（本期 5 个品类池均不足 50 条）。
- **随机性**：`random.seed(42)`，按 `attraction → restaurant → hotel → train_route → flight_route`
  顺序依次抽样，同一份数据重复执行得到同一批样本（可复现）。
- **样本粒度**：一条"样本"= 一个实体（景点/餐厅/酒店/线路），不是单独字段；线路类以线路为实体，
  内部车次/航班整体核对。
- **自动校验规则（静态一致性，可机器判定）**：
  - `attraction`：`address` 非空；`ticket_price` 为数值且 ≥ 0；`open_time` 为 `HH:MM-HH:MM`、`全天`
    或带括号说明的时段。
  - `restaurant`：`address` 非空；`avg_price` 为数值且 > 0。
  - `hotel`：`address` 非空；`price` 为数值且 > 0。
  - `train_route`：车次非空；出发/到达站非空且不相同；时刻为 `HH:MM`；二等/一等座票价 > 0；
    出发到达站名与线路两端城市一致。
  - `flight_route`：航班非空；航班号不重复；起降时刻为 `HH:MM`；经济舱票价 > 0；出发/到达机场非空。
- **错误率定义**：
  - 自动口径：`自动校验命中条目数 / 该品类抽样条目数`（保留 4 位小数）。
  - 人工口径：`人工判定为错误（事实/价格/营业时间/位置有误）条目数 / 核对条目数`。
    本期人工口径尚未回填，列为后续准确性核对的待办。

## 2. 复现命令

```bash
python scripts/sample_baseline.py
# 可选：--out <csv 路径> --per-category <每品类条数> --seed <随机种子>
```

默认输出 `_cache/data-baseline-sample.csv`（UTF-8 BOM，便于 Excel 直接打开），
列为 `category, city, name, expected_fields, auto_issues, verify_result, verify_note`；
`verify_result` 默认 `pending`，由人工核对后改为 `ok` / `wrong`，`verify_note` 记录偏差说明。

## 5. 与后续体检报表的对照方式

- 基线数据（本文件 §3）来自**旧兜底数据模块**；改进后的体检报表来自**数据库实体**
  （`datastore/health_report.py::build_report` 的 `missing_rate / stale_rate / conflict_rate`）。
- 两者口径不完全等价：基线是"字段静态一致性 + 人工准确性"，报表是"缺失/过期/冲突"。
  对比时只比较同一维度：字段缺失对比 `missing_rate`，事实准确性对比人工口径错误率。
- 后续每次体检报表生成后，在本文件追加一节"体检报表对照"，写入生成日期与三个比率，不改动 §3 的基线数值。
